## 1. 这份文档要解决什么

PRD 回答了「做什么」，这份文档回答「长什么样、怎么动、为什么这样」。

判断一份 UI/UX 文档是否合格，我只用一条标准：**前端工程师能不能只看它就把页面做出来，且做出来和设计意图一致。** 所以下面不会出现「简洁大气」「现代感」这类形容词充当结论，每个视觉决定都绑定一个具体问题。

它要解决的具体问题是三个：

其一，**知识产品很容易做成「聊天框 + 侧边栏」的通用 SaaS 模板。** 那样做的代价不是难看，而是**把产品最核心的能力藏起来了**——追溯、定位、验证，这些恰恰是需要被看见的。因此本设计的中心任务是让「可追溯」变成一种可见的视觉语言，而不是一个藏在菜单里的功能。

其二，**开发者用户对信息密度有耐心，对空洞留白没有耐心。** 一屏只放三个大卡片、配一个渐变插画，会被判定为「不专业」。密度要够，但要有秩序。

其三，**长文阅读和数据分析是两种冲突的界面需求。** 前者要大字号、宽行距、窄行宽；后者要小字号、多列、紧凑。本设计用**两套排版尺度**分别服务两者，而不是折中出一套谁都不舒服的中间值。

## 2. 参考作品与借鉴边界

### 2.1 核对状态与方法

本节的对标项目于 **2026-10-31 通过 GitHub REST API 在线核对**。核对项只有五个：仓库是否存在、星数、最近一次推送时间、是否归档、GitHub 标注的 SPDX 许可证标识。

核对命令可复现：

```bash
gh api "repos/<owner>/<repo>" --jq '"\(.full_name)\t\(.stargazers_count)\t\(.pushed_at)\t\(.archived)\t\(.license.spdx_id)"'
```

**仍然没有核对的三件事**，在下文引用时必须继续保留这个边界：

- **许可证的实际条款。** GitHub 的 SPDX 字段只是平台识别结果，部分仓库返回 `NOASSERTION`，不代表没有许可证。商用前必须读 LICENSE 原文。
- **界面是否已改版。** 星数和推送时间不能证明某个页面还在，也不能证明它的交互没变。
- **功能与本文描述是否一致。** 需要把项目实际跑起来逐条对照。

因此下文「借什么」仍然只针对**交互模式与信息架构**，不复制任何代码、图标、文案或像素级视觉。

### 2.4 三条借鉴纪律

**只借模式，不借皮肤。** 上面每一行的「借什么」都是交互或结构层面的，没有一条是「用它的配色」。原因是皮肤可以抄得很像，模式抄不来；而用户感知到的差异，恰恰来自模式。

**不借「看起来很 AI」的视觉。** 紫蓝渐变、发光边框、玻璃拟态、悬浮光球，这些在 2024–2025 年的 AI 产品里高度同质化，且与「可信、可核查」的产品承诺相冲突。本设计刻意避开。

**对标是为了做减法，不是做加法。** 每个借鉴点都必须能追溯到 PRD 的某条需求；追溯不到的不做。例如 Onyx 有很完整的权限体系界面，本产品 V1 单用户，直接不做。

### 2.5 这份对标表的维护规则

第 2 章的表格一旦带上星数与时间，就变成了会过期的数据。为避免它半年后变成误导，定四条：

其一，**每 6 个月复核一次**，复核时更新「核对」列的时间戳；超过 12 个月未复核的行，读的人应当默认它已失效。

其二，**低活跃项目只能作为「稳定基座」，不能作为「交互来源」。** 具体到本项目：Tremor（2025-10 后无推送）只用来参考指标卡的排版层次，不引入其组件库；cmdk（2025-10 后无推送）只参考交互模型，实现上按需自研；Novel（2025-01 后无推送）直接用 Tiptap 替代。这条要落到 6.1 的选型里，而不只是写在 2.3。

其三，**星数不作为采用依据，只作为活跃度信号。** 判断标准始终是「它有没有解决我们某个具体问题」。

其四，**许可证只作线索。** GitHub 的 SPDX 字段、`NOASSERTION` 都不能替代读 LICENSE 原文；商用前单独做一次许可证审查，结论写进技术设计。

## 3. 设计原则

五条，按优先级排列。冲突时上位原则胜出。

**原则一：可追溯性必须可见。** 引用、来源、块边界、版本，这些不是设置里的开关，而是界面上的常驻元素。用户在任何时候都应该能回答「这句话从哪来」。

**原则二：阅读态与操作态分离。** 同一份内容，读的时候要安静（窄行宽、大行距、弱化控件），操作的时候要密集（工具栏、快捷键、多列）。两种态用不同的排版尺度，不做折中。

**原则三：密度服务于扫视，不服务于堆砌。** 高密度不等于塞满。每一屏有一个明确的主任务，其余信息降一级处理（更小的字号、更弱的颜色、可折叠）。

**原则四：状态必须被设计，不能被忽略。** 空（首次 / 筛选后）、加载、错误、部分失败，五种呈现都是设计对象。默认只做「正常态」的实现会被打回。

**原则五：动效只用来解释变化，不用来表演。** 任何动画都必须回答「它在告诉我什么」。答不上来的动画删掉。

## 4. 视觉语言

### 4.1 概念：纸与索引

整套视觉建立在一个隐喻上：**这是一本可以被索引的书。**

「纸」提供阅读的舒适——暖白底、衬线标题、克制的分隔线、接近印刷品的行距。「索引」提供可信的结构——等宽的偏移量标签、块编号、虚线边界、角标。两者叠在一起，形成这个产品独有的气质：**它看起来像在读一份文献，但每一段都能被机器定位。**

这个隐喻不是装饰。它直接导出了三条具体规则：

其一，**内容画布永远是纸色，应用外壳是灰白色。** 内容与工具在视觉上分层，用户一眼能分清「这是材料」和「这是操作」。

其二，**边界用细线和留白表达，不用阴影和卡片堆叠。** 卡片是 SaaS 模板的语言，细线是文献的语言。

其三，**机器生成的信息一律用等宽字体。** 偏移量、块 ID、耗时、版本号、模型名——凡是「机器说的」都用 mono，凡是「人说的」都用 sans 或 serif。这条规则让用户不必阅读内容就能分辨信息性质。

### 4.2 色彩

单一强调色，其余全部中性。理由：知识产品的界面里已经有大量彩色内容（状态、标签、图表），再叠加一个高饱和品牌色会失控。

| 令牌 | 值 | 用途 | 对比度 |
| --- | --- | --- | --- |
| `--paper-0` | `#FFFFFF` | 内容画布 | — |
| `--paper-1` | `#FBFAF7` | 应用背景（暖白） | — |
| `--paper-2` | `#F4F1EA` | 下沉区域、表头、代码块底 | — |
| `--line` | `#E6E1D6` | 常规分隔线 | — |
| `--line-strong` | `#D5CFC0` | 强调分隔、输入框边框 | — |
| `--ink-900` | `#1B1A17` | 主文本 | 16.5:1 on paper-0 |
| `--ink-700` | `#3A3833` | 次级文本 | 10.8:1 |
| `--ink-500` | `#6B675E` | 辅助文本、说明 | 5.6:1 |
| `--ink-400` | `#8C8779` | 占位符、禁用 | 3.6:1（仅用于非关键信息） |
| `--accent` | `#2C5A5F` | 唯一强调色（青黛）：链接、引用角标、选中态、主按钮 | 7.2:1 |
| `--accent-weak` | `#E8F0F0` | 强调底色、选中行背景 | — |
| `--highlight` | `#FBF0D9` | 被引用段落的底色 | — |

| `--danger` | `#9E2B25` | 危险、失败、删除 | 6.4:1 |

**为什么强调色是青黛而不是常见的靛蓝或紫。** 靛蓝已被绝大多数 AI 产品占用，紫是 2023–2025 的 AI 陈词。青黛偏冷、偏灰，与暖白纸色形成低饱和对撞，读久不刺眼，且不与任何语义色（红/黄/绿）混淆。它在正文里作为链接色也足够可辨。

**危险色与强调色的冲突处理。** 两者明度接近，因此在形态上区分：危险状态永远带**实心圆点或实心徽标**，强调色永远只做**文字色或细边框**。任何破坏性按钮不得使用强调色，反之强调色不得用于删除类动作。

**深色主题。** 本文只定义浅色。深色已单独出稿：`UIUX_THEME_DARK.md`，与浅色共用一套语义令牌契约（见 `UIUX_THEME_LIGHT.md` 第 2 章）。两套主题的差异不在色值，而在**层级表达方式**——浅色靠表面明度 + 阴影，深色只能靠表面明度 + 描边。

实现节奏：V1 先交付浅色，深色在同一套令牌下补全，用 `<html data-theme>` 切换；因此**组件从第一行代码起就不得写死色值**，否则补深色时要返工。

### 4.3 字体与排版尺度

无网络字体依赖，全部使用系统字体栈，保证离线可用。

```css
--font-serif: ui-serif, "Iowan Old Style", "Source Serif Pro", Georgia, "Songti SC", "Noto Serif CJK SC", serif;
--font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-mono: ui-monospace, "SF Mono", "JetBrains Mono", Menlo, Consolas, monospace;
```

**两套尺度，按场景切换：**

| 用途 | 字体 | 字号/行高 | 字重 | 场景 |
| --- | --- | --- | --- | --- |
| 页面标题 | serif | 26/34 | 500 | 各页 H1 |
| 区块标题 | serif | 20/28 | 500 | 文档内 H2、面板标题 |
| 正文阅读 | serif | 17/30 | 400 | 文档详情、Wiki 正文 |
| 正文行宽 | — | 最大 68 个字符 | — | 超过则易读性下降 |
| 界面正文 | sans | 14/22 | 400 | 列表、表单、说明 |
| 界面小字 | sans | 12.5/18 | 400 | 辅助信息、时间戳 |
| 数据强调 | sans | 28/34 | 600 | 指标卡主数值，配合 `tabular-nums` |
| 机器信息 | mono | 12/18 | 400 | 偏移量、块 ID、耗时、版本 |
| 代码 | mono | 13/22 | 400 | 代码块 |

**三条排版规则：**

其一，**中文不用衬线做大段正文时，行高必须 ≥ 1.75。** 中文字形密度高，1.5 的行高在长文里会挤。正文 17/30 即 1.76。

其二，**所有数字列使用 `font-variant-numeric: tabular-nums`。** 否则指标卡刷新时数字会跳动，任务耗时列会参差不齐。

其三，**标题层级不超过四级。** 超过四级说明内容组织有问题，应该拆页而不是加字号。

### 4.4 间距、圆角、边框、阴影

**间距。** 4px 基准，常用档位：4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 56 / 72。页面左右内边距在 ≥1280px 时为 32px，1024px 为 24px，768px 为 20px，390px 为 16px。

**圆角。** 输入框与按钮 4px；面板与卡片 8px；抽屉与浮层 12px；标签与角标 999px。**不使用 16px 以上的大圆角**——大圆角会让界面显得轻浮，与文献气质相悖。

**边框。** 一律 1px。分隔用 `--line`，可交互容器用 `--line-strong`。**不通过加粗边框表达状态**，状态用颜色与图标。

**阴影。** 只用于浮层（下拉、抽屉、命令面板）：`0 8px 24px rgba(27,26,23,0.08), 0 1px 2px rgba(27,26,23,0.04)`。页面内元素一律无阴影。

### 4.5 图标与插画

图标用 1.5px 描边的线性图标（Lucide 风格），尺寸 16 / 20 两档。**不使用填充图标**，除了表示选中态的实心圆点。

插画只出现在空状态，且只有一种形式：**极简线稿 + 一句说明**。不做 3D、不做渐变插画、不做角色形象。原因是空状态的作用是引导动作，不是展示美术。

### 4.6 动效

| 场景 | 时长 | 曲线 | 说明 |
| --- | --- | --- | --- |
| 悬停、聚焦 | 120ms | ease-out | 只变颜色和透明度 |
| 面板展开/收起 | 180ms | ease-out | 高度与透明度同步 |
| 抽屉滑入 | 220ms | cubic-bezier(0.2, 0, 0, 1) | 从右侧进入 |
| 引用高亮脉冲 | 1200ms | ease-in-out | 进入时底色渐显，2 秒后渐隐 |
| 流式文本 | 无 | — | 逐字出现，不加淡入，避免视觉抖动 |

**禁止的动效：** 弹性回弹、连续旋转、无限呼吸、悬浮位移、粒子。这些在知识工具里只会分散注意力，且与「减少动效」的无障碍设置冲突。

`prefers-reduced-motion: reduce` 时，所有位移动画降为 0ms，只保留透明度变化。

## 5. 布局系统

### 5.1 三栏骨架

全站采用同一个骨架，只改中栏内容：

```text
┌────┬──────────────┬────────────────────────────┬─────────────┐
│ 56 │  列表/导航栏  │        主内容区             │  证据面板    │
│图标│   320(可折叠) │  fluid, 正文最大 720        │  380(可折叠) │
└────┴──────────────┴────────────────────────────┴─────────────┘
```

**左侧图标栏（56px，常驻）。** 五个入口：总览、知识库、问答、Wiki、设置。**Wiki 在 V1 显示为可点但未开放的说明项**（点击弹一句「Wiki 会在导入材料后自动生成，V1.5 开放」），不做置灰禁用——置灰会被误读为故障。底部放命令面板入口与主题切换。图标栏不放文字标签，悬停显示 tooltip，选中态用 3px 左侧竖条 + 实心底。

**列表栏（320px，可折叠）。** 内容随页面变化：知识库页是文档树/列表，问答页是会话列表，文档详情页是文档内的章节导航。折叠后只留图标栏，主内容区扩展。折叠状态记在会话内，不持久化。

**主内容区（流式，正文上限 720px）。** 表格与仪表盘例外，可占满宽度；阅读类内容强制 720px 上限并居中，避免超宽行导致的阅读疲劳。

**右侧证据面板（380px，可折叠）。** 只出现在两个场景：问答页（引用依据）、文档详情页（元数据与块列表）。设置页与总览页不设右栏。默认展开在 ≥1280px，1024–1279px 默认收起为抽屉，<1024px 为覆盖式抽屉。

### 5.2 断点与行为

| 断点 | 布局 | 变化 |
| --- | --- | --- |
| ≥1440 | 三栏全开 | 正文 720，证据 380 |
| 1280–1439 | 三栏全开 | 正文自适应，证据 360 |
| 1024–1279 | 图标栏 + 主内容 | 列表栏变抽屉，证据面板变抽屉 |
| 768–1023 | 图标栏 + 主内容 | 同上，内边距 20px |
| ≤767 | 顶部栏 + 主内容 | 图标栏变底部 Tab 或顶部抽屉；所有浮层全屏 |

**不做横向滚动。** 任何断点下 `scrollWidth <= innerWidth`，这条是硬验收。

### 5.3 栅格

主内容区内部用 12 列栅格，间距 24px（≥1280）或 16px（<1280）。仪表盘卡片按 6/4/3 列分布，其余页面以单列为主。**不使用嵌套多层栅格**，嵌套超过两层说明布局该简化了。

### 6.3 一个关键元素的详细设计：ChunkBoundary

这是整套设计里最需要解释的组件。

**它解决什么问题。** 用户要能判断「这句话是从哪一段来的」。如果块边界不可见，引用就只是一句「来源：某文档」，等于没做。RAGFlow 和 Logseq 都证明了一件事：**让块成为可指认的对象，用户才会相信系统。**

**怎么画。** 块与块之间不画实线，画一条 1px 虚线，虚线左端悬挂一个 mono 标签，内容为块序号与 token 数。标签默认是 `--ink-400`，鼠标悬停整块时变为 `--accent`。

**什么时候可见。** 三种模式：

- **阅读模式**（默认）：虚线几乎不可见（`--line` 的 40% 透明度），不干扰阅读。
- **检查模式**（点击顶部「显示块」或按 `B`）：虚线加深，标签全部显示。
- **引用模式**（从问答跳转进来）：目标块底色变 `--highlight`，左侧 2px accent 竖条，虚线仅在目标块上下两侧显示。

**为什么默认隐藏。** 如果每条虚线都常显，长文档会变成表格，阅读体验崩坏。默认弱化、按需打开，是密度与可读性的平衡点。

**禁止的做法。** 不要给每个块加卡片边框，不要加圆角背景，不要在块之间加大间距。块是连续的文本流，"切开但不断开"才是正确观感。

### 6.4 第二个关键元素：引用角标

首版把角标写成「上标小方块 + 悬浮 120 字摘要」。按 2.3 收录的 Vercel AI Elements 对照，这个规格低于现在的合理下限，因此本节重写。

**角标的四种状态。**

| 状态 | 外观 | 触发 |
| --- | --- | --- |
| 默认 | 上标小方块，`--accent` 文字 + `--accent-weak` 底 | — |
| 悬浮 / 聚焦 | 底色转 `--accent`，文字转白 | 鼠标进入 120ms 后，或键盘 Tab 聚焦 |
| 多来源 | 角标内显示 `1/3`，右侧加一个 2px 竖分隔 | 该句引用了 2 个以上块 |
| 校验失败 | 角标描边转 `--warning`，图标改为感叹号 | 引用后校验未通过 |

**预览卡（hover card）。** 悬浮 400ms 后出现，位置优先上方、其次下方，距角标 8px。内容三行：

1. 来源文档标题 + 块序号（mono）。
2. 引用原文片段，最多 3 行，超出截断。
3. 底部一行操作：「查看上下文」「第 1 / 3 条」左右切换。

**为什么要有预览卡而不是直接打开右栏。** 打开右栏会挤压正文宽度，打断阅读；而大多数时候用户只需要确认「这句确实有出处」，不需要看完整上下文。预览卡解决 80% 的验证动作，右栏留给剩下 20%。

**多来源的轮播规则。** 一个角标对应多个块时，预览卡内用 `1/3` 左右切换，**不拆成三个角标**。理由：拆开会把一句话的末尾变成 `[1][2][3]`，视觉噪声大，且读者会误以为是三个不同的论断。

**编号规则。** 编号在整条回答内连续递增，跨回答重置；多来源角标只占一个编号，其内部用 `1/N` 二次编号。这样正文里的编号数与「来源」列表的条目数一致。

**触屏行为。** 没有 hover，因此：第一次轻触打开预览卡，第二次轻触卡片进入右栏证据面板，点击卡片外关闭。**不做长按**，长按在移动端与文本选择冲突。

## 7. 页面规格

以下五页均为 V1 范围内，需在首个可交付版本中实现。

### 7.1 Dashboard

**页面任务。** 让用户在 5 秒内判断系统是否健康、下一步该做什么。

**布局。** 三段式纵向：指标带（顶部）→ 双栏（最近导入 2 : 最近任务 1）→ 最近变更（整宽）。

指标带为六个等宽卡，间距 16px，卡片高度 96px，**不使用阴影与渐变**，仅靠 1px 边框与纸色区分。

**信息层级。** 一级是六个数字；二级是数字下方的分解（如「文档 128 · 其中 3 份处理失败」）；三级是可点击的箭头。**不允许出现图表**——六个数字画成折线图只是在填充版面。

**关键交互。**

点击指标卡跳转并带筛选。例如点「失败文档」进入知识库，筛选条件自动设为 `状态=失败`，并在筛选栏上显示一个可移除的「来自总览」标签——**用户必须知道自己为什么只看到 3 条记录**，否则会误以为数据丢了。

任务流支持折叠「已完成」，默认只看进行中与失败。已完成的任务在知识库里本来就能查到，堆在总览里没有意义。

**状态设计。**

| 状态 | 表现 |
| --- | --- |
| 首次空库 | 指标带整体替换为一张引导卡：「还没有任何知识」+ 导入按钮 + 支持格式说明 |
| 加载 | 六张卡各自骨架块，不整页转圈 |
| 单卡失败 | 卡内显示「加载失败 · 重试」，其余卡正常 |
| 全部失败 | 页面级错误 + 「复制诊断信息」 |
| 有失败任务 | 指标卡右上角出现 danger 圆点；任务区置顶失败项 |

**响应式。** ≥1280 六卡一行；1024 三卡两行；768 两卡三行；390 两卡三行，卡高降为 84px，辅助说明折行。

**验收。** 六张卡的数值与知识库、任务中心对应列表的总数一致；任一卡片点击后的筛选条件可被用户看见并清除；空库时不出现任何「0」。

### 7.2 知识库

**页面任务。** 找到一份材料，或导入一份材料。两个任务并列，因此页面顶部同时提供搜索与导入。

**布局。** 列表栏（文档树/标签树）+ 主内容（工具条 + 表格）+（无右侧面板，选中行时右侧滑出详情预览抽屉）。

**工具条。** 高度 56px，从左到右：搜索框（宽 320）、类型筛选、状态筛选、标签筛选、视图切换（表格/卡片）、导入按钮（primary，右对齐）。筛选器以 chip 形式展示已选项，每个 chip 可单独移除，末尾有「清空」。

**表格列。** 标题（弹性，单行截断，hover 显示全名）、类型（图标 + 文字）、状态（徽标）、块数（mono，右对齐）、更新时间（相对时间，hover 显示绝对时间）、操作（hover 出现）。

**关键交互。**

**行点击**进入详情；**行 hover** 右侧出现「更多」菜单（重新处理、查看原文、删除、复制 ID）。**多选**后底部浮出批量操作条，操作条显示「已选 12 项」与可执行动作，**删除类动作需要二次确认并显示影响条数**。

**导入抽屉**分三个 Tab，Tab 切换不重置已选文件。文件 Tab 选择后立刻显示逐项预检结果（格式、大小、是否重复），**重复项在预检阶段就标记出来**，而不是等上传完才说。上传中使用逐项进度条，未开始项显示等待态。

**标签体系。** 首版只写了「筛选 chip」，没有定义标签怎么产生、怎么改，这是缺口。按 Karakeep 的做法补齐四条：

其一，**标签是中性的，不带颜色。** 用 `--paper-2` 底 + `--ink-700` 字，与状态徽标（绿/黄/红）在形态上区分。给标签上色会让页面出现第二种语义色系，与「颜色只表示状态」冲突。

其二，**只在两处出现**：列表行的标题下方（最多显示 2 个，超出显示 `+3`），以及筛选栏。文档详情里可以编辑，但不在阅读区堆标签。

其三，**创建即合并。** 打标签时输入框实时筛选已有标签，回车创建；若输入与已有标签仅差大小写或前后空格，自动并入已有标签，不产生「MCP」和「mcp」两条。

其四，**批量打标是追加，不是覆盖。** 选中 N 项后打标，提供「追加标签」与「移除标签」两个动作，不提供「设为这些标签」——覆盖式操作一旦误点，原有分类全没了。

**状态设计。**

| 状态 | 表现 |
| --- | --- |
| 空库 | 整页引导：线稿 + 「导入第一份材料」+ 三种导入方式按钮 |
| 筛选无结果 | 居中提示「没有符合当前筛选的文档」+ 显示当前筛选 chip + 「清空筛选」 |
| 加载 | 8 行骨架，列宽与真实表格一致（避免跳动） |
| 单行失败 | 该行状态徽标为 danger，行尾出现「重试」 |
| 上传中 | 抽屉内逐项进度；关闭抽屉后右下角出现浮动进度条，可点回 |

**响应式。** <1024 表格转卡片列表，卡片显示标题、类型、状态、时间；筛选收进抽屉；批量操作条改为底部固定条。<420 隐藏「块数」列。

**验收。** 200 个文件导入时逐项进度真实反映每个文件状态；筛选 chip 与筛选结果始终一致；重复文件在预检阶段即被标出。

### 7.3 文档详情

**页面任务。** 让用户确认「这份材料到底说了什么」，并能定位到具体段落。

**布局。** 顶部信息条（64px）+ 左栏正文（最大 720，居中）+ 右栏检查面板（380）。

**信息条。** 面包屑（知识库 / 文档标题）+ 状态 + 版本 + 操作（显示块、重新处理、下载原文、删除）。**版本以 `v2` 形式显示，点击展开版本列表**。

**右栏三个 Tab：**

**信息** —— 来源 URL、导入时间、内容哈希（截断显示，可复制）、字符数、页数、块数、当前向量状态。

**块** —— 全部块的列表，每项显示序号、token 数、类型（文本/代码/表格）、是否曾被检索命中。点击某项，左栏滚动到对应位置并高亮 2 秒。

**日志** —— 处理流水线的步骤时间线，每步含状态、耗时、输出摘要；失败步骤可展开诊断信息。

**关键交互。**

从问答跳转进来时，URL 携带 `?chunk=xxx`，页面加载后**自动滚动到该块并高亮**，同时右栏自动切到「块」Tab 并选中该项。**这条是「引用可验证」的最后一公里**，必须做。

按 `B` 切换块边界显隐。按 `←/→` 在块之间跳转。

PDF 与 Markdown 用同一个阅读容器，但渲染方式不同：PDF 走 pdf.js 的文本层 + 高亮层，Markdown 走自研渲染器。**两者都必须支持「滚动到字符偏移」这个能力**，否则引用定位无法统一。

**状态设计。**

| 状态 | 表现 |
| --- | --- |
| 处理中 | 正文区显示「解析中」+ 当前步骤 + 已用时；右栏「块」Tab 显示占位 |
| 处理失败 | 正文区显示失败步骤、错误码、重试按钮；不显示空白正文 |
| 块定位失败 | 高亮失败时顶部提示「未能定位到该段落，可能因文档已更新」 |
| 文档不存在 | 404 视图，附「返回知识库」，不显示内部 ID |

**响应式。** <1280 右栏变抽屉；<768 信息条只留标题与状态，操作收进「更多」；390 正文内边距 16，字号降到 16/28。

**验收。** 从任意问答引用跳转，目标段落被准确高亮且滚动位置不留半行；块边界切换在三档模式间无闪烁；PDF 与 Markdown 的定位行为一致。

### 7.4 问答

**页面任务。** 提问、读答案、验证引用。三个动作构成一个循环，界面必须让这个循环尽量短。

**布局。** 左栏会话列表（280）+ 中间对话流（流式，最大 760）+ 右栏证据面板（380）。

关于 760 这个宽度：assistant-ui 的 Perplexity 示例用 40rem（约 640px），那是英文行宽。中文单字信息密度更高，按每行 36–38 字计算，720–760 才是舒适区间，因此不照搬 40rem，但**也不超过 760**——再宽会让人读串行。

**中间区从上到下：** 会话标题栏（可重命名）→ 消息流 → 输入区。

**空会话与有会话是两种布局。** 空会话时，输入区**垂直居中**在中间区，上方是标题与三个示例问题，下方留白；发出第一条消息后，输入区下沉到底部并固定。这是 assistant-ui 示例里最值得借的一条：空态居中会让「这里可以输入」这件事不言自明，而固定底部的输入框在空页面上会显得孤单且容易被忽略。

**消息气泡的处理。** 不用气泡。用户消息右对齐、`--paper-2` 底色、圆角 8；助手消息左对齐、**无底色**，直接排在纸面上。理由：气泡会把长回答切成碎片，破坏阅读节奏；而助手回答通常是长文，需要连续阅读。

**回答的排版。**

正文 16/28 sans（问答不是文献，sans 更利落）。引用角标紧跟在被引句子末尾，规格见 6.4：悬浮出预览卡，点击打开右栏，多来源显示 `1/N`。**角标编号在整条回答内连续，跨回答重置。**

回答末尾固定一块「来源」区，列出所有引用到的文档与块，每条含文档名、块序号、一句摘要。**即使正文里已有角标，末尾仍要列出**——用户需要一个可浏览的清单，而不是在正文里找。

**来源区默认只展开前 5 条**，超出时显示「展开全部 12 条」。这个阈值不是拍脑袋：一屏内 5 条来源正好在视线范围内，超过之后用户不会逐条读，只会滚动，而滚动会让他离开回答正文。折叠后计数本身就是信息——「12 条来源」告诉你这条回答的证据密度。

**检索阶段与生成阶段分开显示。** 助手消息先出现「正在检索 12 份文档…」的状态行，检索完成后该行变为「已找到 8 个相关片段」，然后开始流式生成。**这个中间状态必须保留在消息里**，因为它解释了回答的依据来自哪里，也是用户判断「要不要换个问法」的依据。

**输入区。** 左侧一个范围选择器（全部文档 / 标签 / 指定文档），默认「全部」；中间 textarea；右侧是**一个会变形的按钮**，而不是「发送 + 停止」两个。Enter 发送，Shift+Enter 换行。输入框上方显示当前范围，若范围被限制，用一个 accent 色的 chip 提示「仅检索：MCP 相关」。**范围受限必须在输入处可见**，不能只在结果里体现。

**按钮的四态**（采纳 assistant-ui 的做法）：

| 状态 | 图标 | 点击行为 |
| --- | --- | --- |
| 空闲 + 有内容 | 上箭头 | 发送 |
| 空闲 + 无内容 | 上箭头，40% 透明度且禁用 | — |
| 生成中 | 实心方块 | 停止生成 |
| 已停止 | 刷新箭头 | 重新生成 |

**为什么合并成一个按钮。** 两个按钮并排时，用户在生成中会把「发送」误点成第二次提交，而产品规则里重复提交是要被拒绝的。合并后物理上不存在误点路径，比事后报错更可靠。

**听写（语音输入）不在 V1 范围**，但按钮预留右滑展开的位置，避免 V1.5 加功能时重排布局。

**关键交互。**

悬浮角标 400ms → 出预览卡（不打开右栏）；点击角标 → 右栏切到证据面板并滚动到对应项 → 该证据项高亮 1 秒；再次点击同一角标收起右栏。预览卡与右栏是**渐进披露**关系：先给一句原文，再给完整上下文。

证据面板三个 Tab：证据块、检索轨迹、原文。**「检索轨迹」是本产品区别于普通聊天工具的地方**，它展示改写后的查询、每路检索的命中数、融合排名、被重排改变的项。

停止生成：生成中出现「停止」按钮，点击后保留已生成文本并在末尾标注「已停止生成」。

反馈：每条回答底部「有用 / 没用 / 引用有误」。「引用有误」需要选择具体角标编号，**不允许只给布尔值**。

**状态设计。**

| 状态 | 表现 |
| --- | --- |
| 无文档 | 输入框禁用，中间显示「先导入文档才能提问」+ 导入按钮 |
| 无证据 | 回答为「知识库中没有找到相关内容」+ 三条改进建议；不调用模型生成 |
| 检索失败 | 错误卡 + 重试；不降级为模型自身知识 |
| 引用校验失败 | 回答顶部黄色提示条「部分引用无法验证」+ 「查看详情」 |
| 空会话 | 三个示例问题，从用户真实文档标题生成 |
| 加载历史 | 消息骨架，保留滚动位置 |

**响应式。** <1280 右栏变抽屉，角标点击直接打开抽屉；<1024 会话列表变抽屉；<768 中间区占满，输入区固定在底部并处理软键盘遮挡（使用 `dvh` 而非 `vh`）。

**验收。** 角标点击到证据高亮 ≤ 300ms；流式过程中滚动不会被强制拉回底部（用户上滑即暂停自动滚动，出现「回到底部」按钮）；范围受限时输入区可见提示。

### 7.5 设置

**页面任务。** 配置能跑起来，且能验证配置是对的。

**布局。** 左栏分组导航（200）+ 主内容（表单，最大 720）。**不设右栏。**

**分组。** 模型与密钥、检索偏好、处理偏好、存储与数据、关于。

**模型与密钥表单。** 三段（LLM / Embedding / Rerank），每段一张无阴影面板：提供商选择、模型名、API Key、Base URL（可选）、连接测试按钮。

**API Key 字段的特殊处理。** 已配置时显示为 `sk-••••••••4f2a`，右侧「更换」按钮；点击后清空并进入编辑态，**不提供「显示明文」**。这一点是安全要求，不是交互偏好。

**连接测试。** 点击后按钮进入 loading，结果行显示：成功（绿色圆点 + 「连接正常 · 842ms」）或失败（红色圆点 + 可读原因 + 状态码）。**失败原因不得包含上游完整响应体**，只显示归类后的原因。

**危险区。** 位于「存储与数据」底部，1px danger 边框（非填充红底）。清空知识库需输入 `DELETE` 才能启用按钮，且弹窗中列出将被删除的范围。

**状态设计。**

| 状态 | 表现 |
| --- | --- |
| 首次未配置 | 顶部引导横幅「先配置一个模型才能开始」；导航默认停在模型段 |
| 保存中 | 按钮 loading，表单其余部分不禁用 |
| 保存失败 | 字段就地标红 + 顶部 toast；用户输入不清空 |
| 测试中 | 该段按钮 loading，其余段可继续编辑 |

**响应式。** <768 左栏变顶部横向 Tab（可横向滚动，带渐隐遮罩）；260–390 表单单列，段落间用 24px 分隔。

**验收。** Key 在任何网络响应与页面 DOM 中均不出现明文；连接测试失败时给出可操作的原因而非「未知错误」；清空操作需两次确认。

## 8. 关键交互流程

### 8.1 首次使用（零配置到第一次提问）

这是决定留存的一段路径，必须没有断点。

```text
打开应用
  → 【无模型配置】设置页引导横幅 + 表单聚焦
  → 填入提供商与 Key，点连接测试
  → 成功：toast + 自动返回总览
  → 【无文档】总览显示空状态引导
  → 点导入 → 抽屉 → 拖入文件
  → 预检结果 → 确认 → 逐项进度
  → 处理完成（toast + 列表实时更新）
  → 点「问答」→ 示例问题（由刚导入的文档标题生成）
  → 点击示例问题 → 检索 → 流式回答 → 角标
  → 点击角标 → 证据面板 → 原文定位
```

**三个必须做对的点：** 引导不能是弹窗序列（关掉就找不回来）；导入完成到「可以提问」之间不能要求用户手动刷新；示例问题必须来自真实数据，写死的示例会让用户第一次提问就失败。

### 8.2 导入与判重

```text
选择文件 → 前端读文件头校验类型 → 计算哈希
  → 与服务端已有哈希比对（预检接口）
  → 命中：行内标黄「已存在，将跳过」+ 可展开查看已存在的那条
  → 未命中：可上传
  → 上传完成 → 创建文档 → 状态「排队中」
  → 列表行状态由轮询更新（1s → 2s → 5s 递减频率）
```

**关键点。** 预检失败不能让整个抽屉不可用，其余文件仍可上传。判重的提示语气是「提示」不是「错误」——用户导入重复文件是常见行为，不是犯错。

### 8.3 引用验证闭环

这是产品的核心循环，路径必须最短：

```text
读回答 → 看到角标 [3]
  → 点击角标（≤300ms 响应）
  → 右栏证据面板打开并定位到第 3 条
  → 第 3 条显示：文档名 · 块 #012 · 相关度 0.83
  → 点「查看上下文」
  → 打开文档详情，滚动到块 #012，黄色高亮 2 秒
  → 用户判断真假 → 返回（浏览器后退或 Esc）→ 回到问答，位置不丢
```

**「返回后位置不丢」必须实现。** 如果用户验证完引用回到问答，发现滚动位置变了、右栏关掉了，他第二次就不会再点角标了——这个功能就死了。

### 8.4 命令面板（⌘K / Ctrl+K）

命令面板承担三件事：跳转、搜索、执行。这是开发者用户最高频的入口。

| 分组 | 内容 | 触发 |
| --- | --- | --- |
| 跳转 | 总览、知识库、问答、设置 | 输入页面名 |
| 文档 | 模糊匹配文档标题（最多 5 条） | 输入标题片段 |
| 动作 | 导入文档、新建会话、重新处理当前文档、切换块显示、清空搜索 | 输入动作名 |
| 最近 | 最近打开的 5 个文档/会话 | 空查询时显示 |

空查询显示「最近」与「跳转」，输入后按组过滤。↑↓ 选择，Enter 执行，Esc 关闭，Tab 在分组间切换。**支持拼音首字母匹配中文标题**（如输入 `wdck` 命中「文档查看」），这是中文用户的真实习惯。

### 8.5 键盘快捷键总表

| 快捷键 | 动作 | 作用域 |
| --- | --- | --- |
| `⌘/Ctrl + K` | 打开命令面板 | 全局 |
| `G` 然后 `D / L / R / S` | 跳转到总览/知识库/问答/设置 | 全局（非输入态） |
| `B` | 切换块边界显示 | 文档详情 |
| `← / →` | 上一块 / 下一块 | 文档详情 |
| `Enter` | 发送 | 问答输入区 |
| `Shift + Enter` | 换行 | 问答输入区 |
| `Esc` | 关闭浮层 / 停止生成 | 全局 |
| `⌘/Ctrl + Enter` | 强制发送（长文本时） | 问答输入区 |
| `?` | 显示快捷键帮助 | 全局 |

**快捷键不得覆盖输入框内的原生行为**，除 `Esc`。

## 9. 状态设计与文案规范

### 9.1 五种状态的定义

| 状态 | 定义 | 必备元素 |
| --- | --- | --- |
| 空（首次） | 从未有过数据 | 线稿 + 标题 + 一句说明 + 主操作 |
| 空（筛选） | 有数据但当前条件无结果 | 说明当前条件 + 一键清空 |
| 加载 | 数据未到 | 骨架，形状与真实内容一致 |
| 错误 | 请求失败 | 原因 + 重试 + 诊断信息入口 |
| 部分失败 | 列表内个别项失败 | 其余项正常 + 该行错误占位 |

**没有第六种「无权限」**，因为 V1 单用户不存在越权场景。V3 引入令牌后才需要。

### 9.2 文案规范

**七条：**

其一，**说清发生了什么，而不是说「出错了」。** 「解析失败：文件已加密，需要密码」优于「处理失败」。

其二，**给出下一步。** 每条错误文案后面必须跟一个可执行动作，或一句「你可以暂时忽略」。

其三，**不暴露内部实现。** 不出现堆栈、不出现内部 ID、不出现「500」。诊断信息折叠在二级入口。

其四，**不用感叹号。** 感叹号在错误场景里制造焦虑，在成功场景里显得轻浮。

其五，**中文用全角标点，中英文之间加空格。** 数字与单位之间不加空格（`128 份文档` 而非 `128份文档`）。

其六，**空状态不写「暂无数据」。** 这句话没有信息量，用户不知道是该等、该导入、还是该改筛选。

其七，**动词开头。** 按钮文案是「导入文档」而不是「文档导入」；是「重新处理」而不是「处理重试」。

### 9.3 关键文案示例

| 场景 | 文案 |
| --- | --- |
| 空库引导 | 标题「导入第一份材料」· 说明「支持 Markdown、PDF、网页链接，也可以直接粘贴文本」· 按钮「选择文件」 |
| 筛选无结果 | 「没有符合当前筛选的文档」· 「清空筛选」 |
| 检索无证据 | 「你的知识库里没有找到相关内容」· 「试试换一个关键词，或导入更多材料」 |
| 处理失败（可重试） | 「向量化失败：上游服务超时」· 「重试」· 「查看日志」 |
| 处理失败（不可重试） | 「无法解析：文件已加密」· 「请移除密码后重新导入」· 无重试按钮 |
| 引用不可验证 | 「部分引用无法验证，回答可能包含推断内容」· 「查看详情」 |
| 存储占用 | 「已使用 1.2 GB · 其中原始文件 1.1 GB」 |

## 10. 响应式规则

### 10.1 四个必须验证的宽度

390（iPhone 14 逻辑宽）、768（平板竖）、1024（平板横/小笔记本）、1440（桌面）。每个页面在这四档都要截图留档。

### 10.2 布局转换策略

**表格 → 卡片** 在 1024 以下发生。转换后保留标题、状态、时间三个字段，其余进详情。

**三栏 → 两栏 → 单栏** 按 5.2 的断点执行。列表栏与证据面板永远不叠加成两个抽屉，同一时刻最多一个抽屉打开。

**输入区** 在移动端固定底部，用 `100dvh` 计算高度，键盘弹起时输入框上移而不是被遮挡。

### 10.3 触摸目标

所有可点击元素最小 44×44 的触摸区域（视觉尺寸可小于此，用 padding 补足）。列表行的操作按钮在触摸设备上常显，不依赖 hover。

### 10.4 不允许出现的情况

横向滚动、文字被截断且无展开方式、浮层超出视口、固定元素遮挡内容、字号小于 12px 的正文。

## 11. 可访问性

目标不是通过某个工具评分，而是**让键盘用户和低视力用户能用完整流程**。

**对比度。** 正文 ≥ 4.5:1，大字 ≥ 3:1，UI 边框 ≥ 3:1。`--ink-400` 只用于占位符与禁用态，不承载信息。

**焦点。** 所有可交互元素有 `:focus-visible` 样式：2px accent 描边 + 2px 偏移。**不移除默认 outline**，只替换样式。

**语义。** 用真实元素（`button`、`table`、`nav`），不用 `div` 模拟。图标按钮必须有 `aria-label`。表单控件必须有可见 label，不靠 placeholder 充当 label。

**状态播报。** 处理状态变化、流式回答开始与结束、任务失败，使用 `aria-live="polite"`；错误使用 `role="alert"`。

**焦点管理。** 打开抽屉/弹窗时焦点移入并困住；关闭时归还给触发元素。这条最容易漏，必须在验收清单里。

**动效偏好。** `prefers-reduced-motion: reduce` 时，位移动画降为 0，仅保留透明度过渡。

**键盘可达的完整路径。** 导入 → 打开文档 → 提问 → 打开引用 → 返回，全程不碰鼠标。这条是硬验收。

### 12.2 与 Tailwind / shadcn 的映射

shadcn/ui 的主题约定是把语义色映射为 `--background`、`--foreground`、`--primary` 等。本项目保留自己的原始令牌，再映射一层：

| shadcn 变量 | 映射到 |
| --- | --- |
| `--background` | `--paper-1` |
| `--foreground` | `--ink-900` |
| `--card` | `--paper-0` |
| `--border` | `--line` |
| `--primary` | `--accent` |
| `--primary-foreground` | `--paper-0` |
| `--muted` | `--paper-2` |
| `--muted-foreground` | `--ink-500` |
| `--destructive` | `--danger` |

**不要直接把十六进制写进组件。** 组件只使用语义变量，这样未来加浅/深主题时无需改动组件。

### 12.3 深色主题

完整规格见 `docs/UIUX_THEME_DARK.md`。这里只留三条结论，避免读者按「反相」去理解：

其一，**深色不是加一套变量就完事。** 浅色靠阴影表达层级，深色下阴影不可见，必须改成表面明度分级 + 1px 描边，这是结构变化，不是配色变化。

其二，**`--on-accent` 必须反相。** 浅色主按钮是深底白字，深色下强调色被提亮，白字对比度只剩 2.7:1，必须改成亮底深字。

其三，**引用高亮要换色相。** 浅色的 `#FBF0D9` 在暗背景上会变成一块发光区，深色改用 `#3A2F1C` 的微暖暗块。

## 13. 原型说明

配套文件：`design/prototype.html`，单文件、零外部依赖、可直接双击用浏览器打开。

### 13.1 原型覆盖了什么

原型现在的定位是**「全版本设计演示」**——四个版本共用同一个文件，避免每版各做一份、彼此不一致。

它包含五个 V1 页面：指标卡跳转与筛选回填、知识库表格与导入抽屉（含预检与逐项进度）、文档详情（块边界三档切换、块定位高亮）、问答（两阶段状态、流式输出、角标 → 证据面板 → 原文定位）、设置（密钥掩码、连接测试的加载与结果）；Wiki 的阅读态与待审核态（V1.5）；以及三个 V2/V3 静态视图：知识图谱（固定坐标的两跳邻域、节点详情）、Agent Studio（配置表单、工具开关、执行时间线回放）、MCP 接入（令牌列表、四步向导、一次性密钥、调用日志）。另有 ⌘K 命令面板与主题切换开关。

**V2/V3 的三个视图只验证交互骨架，不验证算法。** 图谱节点的坐标是写死的，不代表真实布局效果；MCP 向导不校验真实令牌。它们的用途是让评审能点着走一遍流程，而不是证明功能可用。

### 13.2 原型不是什么

原型中的数据是**演示数据**，不连后端；流式输出是定时器模拟的，不代表真实延迟；命令面板的模糊搜索是简化实现。**原型只用于确认视觉方向与交互结构，不是生产代码**，不应被直接复制进 `apps/web`。

已知未实现、且不影响方向判断的部分：跨文档引用定位（点击第 3 条来源只提示，因为原型只有一份文档正文）、拼音首字母搜索、深色主题、真实文件上传（用假进度条代替）、任务中心独立页（只在总览里体现）。另有两条是本轮文档升级后原型尚未跟上的：**角标预览卡与多来源 `1/N`（6.4）**、**空会话居中 composer 与发送按钮四态（7.4）**。这两条需要在原型下一版补，否则评审时会看到文档比原型更进一步。

这一点必须写明，因为过去最常见的翻车方式是「原型被当成成品交付」。

### 13.3 走查清单

评审时按顺序点一遍，任何一步卡住都记为问题：

1. 打开 → 看到总览 → 点「失败文档」卡 → 是否跳到知识库且筛选可见、可清除。
2. 知识库 → 点导入 → 拖/选 3 个文件（其中 1 个重复）→ 预检是否标出重复。
3. 打开一份文档 → 按 `B` → 块边界是否出现 → 点右栏某块 → 正文是否定位。
4. 问答 → 点示例问题 → 是否先显示「检索中」再流式生成。
5. 点回答里的角标 → 右栏证据是否定位 → 点「查看上下文」→ 是否跳到文档并高亮。
6. 完成后按 Esc 返回 → 问答位置是否保持。
7. 设置 → 点连接测试 → 是否 loading → 结果是否为可读原因。
8. 任意页面按 `⌘K` → 输入「文档」→ Enter → 是否跳转。
9. 浏览器缩到 390 宽 → 是否无横向滚动。

## 14. 与 PRD 的差异与待确认项

| 编号 | 事项 | 说明 | 建议 |
| --- | --- | --- | --- |
| UX-1 | **深色主题已出稿、未实现** | PRD 22.1 要求深浅切换后无对比度问题。现已产出 `UIUX_THEME_LIGHT.md` 与 `UIUX_THEME_DARK.md`，但 V1 代码仍只实现浅色 | 实现顺序：浅色先上，深色用同一套语义令牌补齐；两套共用 `data-theme` 切换，组件禁止写死色值 |
| UX-2 | **提问不需要登录，但设置需要密钥** | 首次使用必须配置模型才能提问，这与「打开就能用」的预期有落差 | 提供「本地模型」检测：检测到本地运行时自动填入，减少一步 |
| UX-3 | **证据面板与文档详情的信息重复** | 两处都展示块内容与来源 | 接受重复。问答场景需要不离开对话就能验证，跳页会打断思考 |
| UX-4 | **Wiki 入口在 V1 置灰** | 置灰入口会让用户误以为功能损坏 | 改为不可见的说明项：点击弹出一句话「Wiki 会在导入材料后自动生成，V1.5 开放」，不显示为禁用按钮 |
| UX-5 | **命令面板的拼音匹配成本** | 支持拼音首字母需要引入额外依赖或自建映射 | 首版只做中文与英文子串匹配，拼音放 V1.1；若目标用户主要用英文，可省 |
| UX-6 | **PDF 与 Markdown 的定位一致性** | 两套渲染器要实现同一个「滚动到偏移」能力 | 定义为渲染器的统一接口契约，做进技术设计，不能各写各的 |
| UX-7 | **引用角标升级为非平凡组件** | 6.4 新增了预览卡、多来源 `1/N`、触屏两段式，实现量从「一个 span」变成「一个有定位逻辑的浮层」 | 需要在技术设计里定浮层的定位与碰撞策略，并在原型中验证；不能只当样式改 | 
| UX-8 | **命令面板的依赖风险** | cmdk 近一年无推送（2025-10），不适合作为长期依赖 | 交互模型照抄，实现自研（约 200 行）或 fork 后自行维护，二选一写进技术设计 |
| UX-9 | **指标卡不应依赖 Tremor** | Tremor 同样处于低活跃，且本产品只需要「主数值 + 分解 + 可点击」三层结构 | 用语义令牌自绘，不引入组件库；Chart 类需求 V1 没有，不必提前引入 |
| UX-10 | **空会话到有会话的布局跳变** | 输入区从居中变为底部固定，若直接切换会产生一次明显位移 | 首条消息发送时用 180ms 的 `ease-out` 位移过渡，且只做一次；`prefers-reduced-motion` 下直接切换 |
| UX-11 | **原型与文档已不同步** | 原型已扩展到 V1.5（Wiki 可点、含审核态），而 V1 文档仍按五页描述；且原型角标还是旧样式 | 要么把原型定位为「V1+V1.5 合并演示」，在 13 章注明；要么拆一份 V1 专用原型。二选一，别让评审时对不上 |
