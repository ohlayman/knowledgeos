## 1. 这一版新增的设计任务

V1 的界面回答的是「我有什么材料」。V1.5 要回答两个新问题：

**问题一：这个知识是谁说的、依据什么。** V1 已经有引用角标解决「来源」，但 Wiki 页面是**合成的**，读者需要区分「这句是原文的转述」和「这句是模型的归纳」。这是新问题。

**问题二：我可以改吗、改了会发生什么。** 审核界面不是「确认弹窗」，它是一个**决策界面**。用户要在一屏内判断接受还是拒绝，判断依据必须齐全。

这两个问题决定了本版新增的四类元素：证据锚点、状态徽章、冲突横幅、段落级 diff。其余全部沿用 V1。

### 1.1 设计原则的补充

V1 的五条原则继续有效，本版追加两条，优先级低于原有五条：

**原则六：合成内容必须与原始内容在视觉上可区分。** 读者不应该需要点开才知道某句话是模型写的。

**原则七：审核界的密度要高于阅读界。** 审核是工作，不是阅读。同一屏里要能同时看到「改了什么、依据是什么、会影响什么」，因此字号更小、分栏更多。

## 2. 新增的四个核心元素

### 2.1 证据锚点（EvidenceAnchor）

**它是什么。** 每个 Wiki 段落右侧（阅读态）或段落末尾（编辑态）的一个小圆点，颜色取决于证据状态。

| 状态 | 外观 | 含义 |
| --- | --- | --- |
| 已锚定 | 实心小圆点，`--accent` | 至少一个有效证据块 |
| 多源 | 实心圆点 + 右侧细分数 | 2 个以上来源，点开看列表 |
| 弱证据 | 空心圆环，`--warning` | 有证据但相关度低于阈值 |
| 无证据 | 空心圆环，`--ink-400` | 模型生成且未挂证据，**此类段落不得出现在已发布页面** |

**为什么用圆点而不是角标数字。** 阅读 Wiki 时，用户不需要立刻知道「这是第 3 条引用」，他需要知道「这段有没有依据」。数字角标在 V1 的问答里有效，是因为那里每条引用都是可点开的具体对象；Wiki 里一段可能对应多个块，数字会变成噪声。想看具体来源，点开圆点即可。

**交互。** 悬浮显示该段落的第一条证据摘要（120 字）与来源标题；点击打开右侧「来源」面板并定位。

### 2.2 状态徽章（WikiStatus）

页面级状态，出现在标题下方、导航树条目上、以及列表里。

| 状态 | 样式 | 文案 |
| --- | --- | --- |
| 已发布 | 实心绿点 + 「已发布」 | `--success` |
| 待审核 | 实心黄点 + 「待审核 2」 | `--warning` |
| 草稿 | 空心灰点 + 「草稿」 | `--ink-400` |
| 可能过期 | 实心黄点 + 「可能过期」 | `--warning` |
| 有争议 | 实心红点 + 「1 处未裁决」 | `--danger` |
| 已归档 | 空心灰点 + 「已归档」 | `--ink-400`，整行降低透明度 |

**多状态并存规则。** 一个页面可以同时「可能过期」且「有争议」。此时徽章区横向排列两个，**危险级优先显示**。不允许用一个复合徽章把两种状态糊成「异常」。

### 2.3 冲突横幅（ConflictBanner）

出现在页面正文顶部、目录之后。1px `--danger` 边框、浅红底（`#FAEFEE`），左侧 3px 实线。

内容结构：一句结论 + 两个来源的并列摘要 + 「裁决」按钮。

```text
本页存在 1 处未裁决冲突
「默认超时」：来源 A 说是 60 秒，来源 B 说是 30 秒          [查看双方说法] [裁决]
```

**为什么不用弹窗。** 冲突是页面的长期状态，不是一次性事件。弹窗关掉就忘，横幅留在页面上，读者每次来都知道这里有分歧。

**为什么不用红色整块填充。** 整块红底会让页面显得「坏了」。这是「存在分歧」，不是「系统故障」，视觉强度要匹配语义强度。

### 2.4 段落级 diff（ParagraphDiff）

审核与版本对照共用。

| 变更 | 呈现 |
| --- | --- |
| 新增段落 | 整段浅绿底（`#F0F6EE`），左侧 2px `--success` 竖条，段首标「新增」 |
| 删除段落 | 整段浅红底（`#FAEFEE`），文字加删除线，左侧 2px `--danger` 竖条 |
| 修改段落 | 段落内逐句标注：删除句加删除线，新增句浅绿底；**不做字符级 diff**，中文逐字 diff 噪声太大 |

**为什么不做字符级 diff。** 中文的字符级 diff 在措辞微调时会产生大量碎片高亮，读起来比原文更累。句子级是中文技术文本的最小可读单位。

## 3. 页面规格

### 3.1 Wiki 首页

**任务。** 让用户看到知识体系的全貌，并知道哪里需要自己介入。

**布局。** 左栏页面树 + 主内容（概览 + 列表）+ 无右栏。

**页面树。** 按六种类型分组，每组可折叠，组内按最近更新排序。树节点显示：标题、状态点、待审数字（若有）。顶部有搜索框与「只看待办」开关。

**主内容三段：**

**第一段：待办条。** 如果有待审核 / 过期 / 冲突，顶部出现一条横向摘要：「3 条待审 · 1 个页面可能过期 · 1 处冲突」，每一项可点击进入队列。**没有待办时这一段完全不出现**，不显示「暂无待办」。

**第二段：最近更新。** 六个页面卡片，显示标题、类型、一段摘要、变更统计（`+3 段 / -1 段`）、时间。卡片无阴影，1px 边框。

**第三段：按类型浏览。** 六组入口，每组显示页面数与最近一页。

**空状态。** 尚未生成任何页面时：说明「Wiki 会随材料自动生成，当前已处理 128 份文档，尚未产生页面」，并给出「手动重建」按钮与可能的三种原因（实体太少、材料过于分散、抽取被关闭）。

**验收。** 待办条上的数字与队列实际条数一致；点击任一待办项进入对应筛选。

---

### 3.2 Wiki 页面阅读

**任务。** 读懂一个概念，并确认它可信。

**布局。** 左栏页面树（可折叠）+ 主内容（正文最大 720）+ 右栏「来源与关联」面板（360）。

**正文区自上而下：**

1. **标题区**：标题（serif，30/40）、状态徽章组、最后更新与最后审核时间、操作（编辑、历史、归档）。
2. **摘要**：1–2 句，`--ink-700`，与正文用一条细线分隔。摘要若为模型生成未经确认，前面加一个「待确认摘要」的小标记。
3. **冲突横幅**（若有）。
4. **正文**：按模板章节组织，每段右侧挂证据锚点。段落之间间距 20px，不用分隔线——**页面是连续阅读的，不是卡片堆叠**。
5. **反链区**：标题「被 4 个页面引用」，每条一行：来源页面名 + 该处上下文一句 + 跳转箭头。
6. **来源区**：本页引用到的所有文档与块，按出现顺序排列。

**右栏三个 Tab：**

**关联** —— 出链（本页链接到的页面，带关系类型）、反链（同上但只列页面名）、相关但未链接的页面建议（**标注为建议，不是事实**）。

**来源** —— 全部证据块列表，每条含来源文档、块序号、相关度、摘录；点击可定位原文。

**版本** —— 版本列表，含版本号、编辑者类型（模型/人工/回滚）、变更摘要、时间。点击任两项进入对照视图。

**关键交互。**

证据锚点 hover 出摘要，点击打开右栏「来源」并定位。**锚点不跳页**——阅读中途跳走会打断理解，V1 的引用跳页在问答场景合适，在 Wiki 阅读场景不合适。

双链点击直接跳转，页面滚动位置重置到顶部。**不做页内锚点跳转**，跨页跳转要的是完整上下文。

`←/→` 在页面树中切换相邻页面；`E` 进入编辑。

**状态。**

| 状态 | 表现 |
| --- | --- |
| 页面不存在 | 404 视图 + 「搜索相近标题」+ 「新建此页面」 |
| 待审核中 | 正文顶部显示「有 2 条待审提案」，正文仍显示已发布版本，不预览提案内容 |
| 可能过期 | 顶部黄条：「本页引用的 1 份来源已更新，内容可能过时」+ 「复核」 |
| 有争议 | 冲突横幅 |
| 加载 | 正文骨架（按段落形状），右栏独立骨架 |

**响应式。** <1280 右栏变抽屉；<768 页面树变抽屉；390 正文 16/28，锚点移到段末而不是右侧（避免压字）。

---

### 3.3 Wiki 编辑器

**任务。** 让人工修改能高效完成，且不破坏证据结构。

**布局。** 全宽两栏：左编辑（Markdown + 段落标记）、右预览（渲染后效果）。顶部工具条，底部状态栏。

**编辑器的特殊之处。** 它不是普通 Markdown 编辑器，因为段落是有身份的：

- 每个段落前有一个 `¶` 标记，悬停显示段落 ID 与证据数量。
- 插入新段落时，编辑器要求**先选证据**或显式标记「人工观点（无证据）」。后者会在预览里显示为无证据段落，只允许在人工编辑时存在。
- 删除段落不物理删除，而是标记为「待移除」，保存后生成删除变更。

**工具条。** 加粗、链接、引用来源、插入段落、插入冲突标记、保存草稿、提交发布。

**未保存保护。** 离开时若有未保存改动，弹出二选一：保存草稿 / 放弃。**不提供「取消」，因为取消容易误点。**

**实时校验。** 无证据段落、失效链接、超长段落，在预览区对应位置标出，不阻断保存但计数显示在状态栏。

---

### 3.4 版本对照

**布局。** 顶部版本选择器（左右各一个下拉）+ 中间并排两栏 + 底部变更统计。

**交互。** 默认对比「上一版 vs 当前版」。支持任意两版。段落级 diff，可折叠未变更段落（默认折叠，只显示变更及上下各一段）。

**要求。** 变更段落数超过 20 时，顶部显示「本次变更较大」，并默认按章节分组折叠。

---

### 3.5 审核队列

**任务。** 用最少的时间处理最多的高价值决策。

**布局。** 左栏队列（320）+ 主内容（提案详情）+ 右栏证据（360）。

**左栏。** 顶部筛选（全部 / 提案 / 过期复核 / 冲突），下方按影响面排序的卡片列表。每张卡显示：目标页面、变更类型、diff 统计、来源文档、生成时间、影响面标识（被引用次数）。**已选中的卡片左侧有 3px 竖条。**

**主内容（提案详情）四块：**

**块一：结论。** 「将在『Hybrid Retrieval』新增 1 段、修改 1 段」+ 一句话变更摘要。**先给结论再给细节**，审核者需要立刻知道这条值不值得细看。

**块二：diff。** 段落级变更，新增/修改/删除各自着色。修改段落的每一段旁边有证据锚点。

**块三：冲突（若有）。** 并列两个说法，各自带来源与时间，中间是「保留 A / 保留 B / 都保留并标注 / 都不采纳」四个选项。

**块四：影响。** 「本页被 4 个页面引用，本次修改涉及其中 2 个页面的相关段落」，附受影响页面列表。**这一块最容易被砍掉，但砍掉之后审核者无法判断风险。**

**底部操作条**（sticky）：拒绝、改写后接受、接受。拒绝需先选原因，未选时「拒绝」按钮启用但点击后弹出原因选择，不预先禁用（预先禁用会让人不知道为什么点不了）。

**批量模式。** 列表支持多选，选中后底部出现批量条。**只有「纯新增段落」的提案可批量接受**，其余类型的复选框置灰并说明原因。

**键盘。** `J/K` 上下切换提案，`A` 接受，`R` 拒绝（打开原因选择），`E` 改写后接受，`P` 折叠/展开证据面板。

**状态。**

| 状态 | 表现 |
| --- | --- |
| 队列为空 | 「没有待审核的提案」+ 一句说明「新文档处理完成后会自动生成提案」 |
| 提案已失效 | 卡片标灰 + 「基于旧版本，已失效」+ 只能查看不能操作 |
| 版本冲突 | 接受时提示「页面已更新，正在重新计算差异」，成功后显示新 diff |
| 批量部分失败 | 显示成功 N 条、失败 M 条与失败原因 |

**响应式。** <1280 证据面板变抽屉；<1024 队列变抽屉，进入详情后隐藏队列；390 只保留详情与底部操作条。

---

### 3.6 冲突裁决

**布局。** 双栏并列：左「说法 A」、右「说法 B」、中间分隔。每栏含：表述、来源文档、块内容、时间、相关度。

**底部四个选项**（单选）+ 理由输入（可选）+ 确认。

**裁决后的呈现。** 页面冲突横幅消失，但正文中保留「历史分歧」折叠块，可展开查看当时的两种说法与裁决理由。**裁决不是删除历史，是把争议折叠起来。**

## 5. 状态与文案

| 场景 | 文案 |
| --- | --- |
| 无证据段落（阅读态） | 不出现。若出现，说明数据异常，显示「该段缺少来源」并允许举报 |
| 提案失效 | 「该提案基于旧版本生成，页面已更新，无法直接应用」 |
| 接受时版本冲突 | 「页面在你审核期间有新版本，已按最新内容重新计算差异」 |
| 无待办 | 「没有待审核的提案。新文档处理完成后会自动生成」 |
| 过期复核 | 「本页引用的 1 份来源已更新。请确认内容是否仍然成立」 |
| 冲突裁决后 | 「已记录裁决。历史说法保留在版本记录中」 |
| 拒绝原因必填 | 「请选择拒绝原因，便于我们改进提案质量」 |
| 归档确认 | 「归档后页面不再出现在检索与列表中，历史版本保留」 |
| 无证据的人工段落 | 「此为人工观点，未关联来源」 |

**语气要求。** 审核界面的文案要**中性、可操作**，不要替用户判断。不写「这条提案看起来不错」，也不写「系统检测到问题」。

## 6. 响应式与可访问性

**断点行为** 沿用 V1 的四档（1440 / 1024 / 768 / 390），审核队列与版本对照额外规定：

- 版本对照在 <1024 改为上下堆叠，而不是左右并排（并排在窄屏无法阅读）。
- 审核队列在 <768 只显示当前提案，队列通过顶部返回进入。
- 冲突裁决在 <768 改为单栏 + 分段切换（说法 A / 说法 B）。

**可访问性要求。**

状态不能只靠颜色：徽章必须有文字，证据锚点必须有 `aria-label`（如「本节有 2 条来源」）。

diff 的颜色差异必须同时有文字标记（「新增」「删除」），不能只靠底色。这对色觉障碍用户是硬要求。

审核队列的键盘操作必须完整：`J/K` 切换、`A/R/E` 操作、`Esc` 返回列表。

冲突横幅与状态变化使用 `aria-live="polite"`。

## 7. 设计验收

- DV15-1：任一页面，非导语段落 100% 带证据锚点，锚点状态与实际数据一致。
- DV15-2：页面同时存在「可能过期」与「有争议」时，两个徽章都可见且危险级在前。
- DV15-3：提案详情在一屏内（1440×900）能看完结论、diff、证据入口、影响范围四项，无需滚动超过一屏。
- DV15-4：拒绝提案未选原因时无法提交，且给出明确提示。
- DV15-5：版本对照在任意两版之间可切换，未变更段落默认折叠。
- DV15-6：审核队列 `J/K/A/R/E` 五个键全部可用，焦点位置始终可见。
- DV15-7：390 宽下审核详情无横向滚动，底部操作条不被遮挡。
