## 1. 深色不是反相

把浅色取反，会得到三个必然的坏结果：纯黑底配纯白字（对比过强、边界消失）、灰调发脏（暖白反相后是冷灰，与「纸与索引」的气质断裂）、层级全丢（浅色靠阴影分层，深色里阴影根本看不见）。

所以深色主题要重新回答三个问题：

**问题一：层级怎么表达？** 浅色靠「白纸 + 淡阴影」，深色必须改成**靠表面明度分级**——越靠上的界面，底色越亮。这是本轮的核心结构调整。

**问题二：色相怎么保留？** 暖白反相是冷灰。要保住「纸」的暖调，深色底必须带一点红黄（`#191715`，R > G > B），而不是中性 `#1A1A1A`。

**问题三：颜色怎么降刺激？** 大面积深色背景会让高饱和色产生眩光。所有语义色都要**降饱和、提明度**，而不是沿用浅色的浓度。

---

## 2. 三条硬原则

**原则一：不用纯黑。** 底色最深处到 `#121110` 为止。纯黑在 OLED 上会有拖影，且与任何深色元素对比过强，边界反而糊成一团。

**原则二：不用纯白文字。** 主文本 `#EDE9E0`，带暖调。纯白在暗底上会产生光晕（halation），长时间阅读会累。

**原则三：不用阴影表达层级。** 阴影在深色背景下几乎不可见。层级一律由表面明度 + 1px 亮色描边表达；阴影只用于真正脱离文档流的浮层，且必须同时有一条顶部内高光。

## 3. 令牌取值

### 3.1 表面层级

深色的层级顺序与浅色**相反**：浅色是「越靠上越白」，深色是「越靠上越亮」。

| 令牌 | 取值 | 用途 | 相对画布 |
| --- | --- | --- | --- |
| `--surface-app` | `#121110` | 应用外壳、图标栏、侧栏 | 最暗 |
| `--surface-canvas` | `#191715` | 内容画布、正文 | 基准 |
| `--surface-sunken` | `#211E1A` | 表头、代码块、用户气泡、下沉区 | 略亮 |
| `--surface-raised` | `#24211D` | 抽屉、弹层、命令面板 | 最亮 |

**为什么下沉区反而更亮。** 浅色里「下沉」意味着更接近阴影，所以更暗；深色里没有阴影可用，如果让下沉区更暗，它会与最暗的外壳混在一起，看不出这是一个独立区域。因此深色下「下沉」改为「内嵌」——用略亮的底 + 顶部 1px 亮线表达凹陷。

### 3.2 文本

| 令牌 | 取值 | 对比度（on `#191715`） | 用途 |
| --- | --- | --- | --- |
| `--text-primary` | `#EDE9E0` | 14.7:1 | 主文本 |
| `--text-secondary` | `#C4BEB2` | 9.7:1 | 次级文本 |
| `--text-muted` | `#938D80` | 5.4:1 | 辅助信息、时间戳 |
| `--text-disabled` | `#6B665C` | 3.1:1 | 禁用、占位符 |

**注意 `--text-muted` 只有 5.4:1。** 它在深色下比浅色的 5.6:1 略低，已经接近 AA 的边界。因此深色主题里 **12px 以下的正文不得使用 muted**，只能用于 12.5px 以上的辅助信息；小于 12px 时改用 `--text-secondary`。

### 3.3 边框

| 令牌 | 取值 | 对比度 | 用途 |
| --- | --- | --- | --- |
| `--line-subtle` | `#2C2925` | 1.2:1 | 发丝分隔 |
| `--line` | `#3A352E` | 1.5:1 | 卡片边框、面板分隔 |
| `--line-control` | `#6E675A` | 3.2:1 | **可交互控件边界** |

**深色的控件边框必须显著亮于分隔线。** 这是深色主题最容易翻车的地方：设计稿里看着「有边框」，到了暗屏上因为 gamma 问题直接消失，用户找不到输入框在哪。

### 3.4 强调与语义

| 令牌 | 取值 | 对比度 | 说明 |
| --- | --- | --- | --- |
| `--accent` | `#6FA8A6` | 6.7:1 | 由浅色 `#2C5A5F` 提亮降饱和 |
| `--accent-weak` | `#1B2A2A` | — | 选中行、角标底 |
| `--accent-border` | `#2F4A4A` | — | 角标描边 |
| `--on-accent` | `#121110` | 7.0:1 on accent | 强调色上的文字改用深色 |
| `--highlight` | `#3A2F1C` | — | 被引用段落底 |
| `--success` | `#7FA276` | 6.2:1 | 降饱和提亮 |
| `--warning` | `#D6A45C` | 7.9:1 | — |
| `--danger` | `#E07A70` | 6.1:1 | 由 `#9E2B25` 提亮，避免暗红在黑底上「沉下去」 |
| `--state-success-bg` | `#1E2A1D` | — | 成功底纹 |
| `--state-success-border` | `#3C5538` | — | — |
| `--state-warn-bg` | `#2E2618` | — | 警告底纹 |
| `--state-warn-border` | `#5C4A2A` | — | — |
| `--state-danger-bg` | `#2E1D1C` | — | 危险底纹 |
| `--state-danger-border` | `#5E3A36` | — | — |

**关键判断：`--on-accent` 必须改成深色。** 浅色主题里强调按钮是「深底白字」，深色主题里如果继续用白字，白字落在提亮后的青色上只有 2.7:1，不可读。所以深色下主按钮是「亮底深字」——这也恰好是深色界面里更常见的处理。

### 3.5 状态色在底纹上的对比

| 组合 | 对比度 |
| --- | --- |
| `--success` on `--state-success-bg` | 5.2:1 |
| `--warning` on `--state-warn-bg` | 6.6:1 |
| `--danger` on `--state-danger-bg` | 5.5:1 |
| `--text-primary` on `--highlight` | 10.8:1 |

### 3.6 阴影与遮罩

| 令牌 | 取值 |
| --- | --- |
| `--shadow-overlay` | `0 8px 24px rgba(0,0,0,.45), 0 1px 0 rgba(255,255,255,.04) inset` |
| `--scrim` | `rgba(0,0,0,.56)` |
| `--docbar-bg` | `rgba(18,17,16,.92)` |
| `--toast-bg` | `#EDE9E0` |
| `--toast-fg` | `#171614` |

**遮罩要更重。** 浅色下 28% 的黑已经能压住背景，深色下同样数值几乎看不出压暗效果，必须提到 56%。

**Toast 要反色。** 深色界面里再放一个深色 toast，它会和背景糊在一起；改成浅底深字，反而更像「浮起来的一张纸」，与产品隐喻一致。

## 4. 组件适配

### 4.1 卡片与面板

深色下**取消卡片阴影**，改用：`--surface-canvas` 底 + 1px `--line` 边框。卡片之间的间距比浅色**大 4px**——没有阴影后，间距是唯一的分离手段。

### 4.2 按钮

| 变体 | 背景 | 文字 | 边框 |
| --- | --- | --- | --- |
| primary | `--accent` | `--on-accent` | 无 |
| secondary | `--surface-sunken` | `--text-primary` | `--line-control` |
| ghost | 透明 | `--text-secondary` | 无 |
| danger | 透明 | `--danger` | `--state-danger-border` |

secondary 用 `--surface-sunken` 而不是画布色：深色下画布色与背景太接近，按钮会「陷进去」。

### 4.3 输入控件

- 边框 `--line-control`（3.2:1），这是深色里最不能省的一笔。
- 背景 `--surface-sunken`，比画布略亮，形成可输入的凹陷感。
- 聚焦环 2px `--accent`，外扩 2px。**深色下聚焦环要比浅色多 1px 外扩**，否则在暗背景上不够显眼。
- 占位符 `--text-disabled`（3.1:1），仅作提示，不承载信息。

### 4.4 徽标与状态点

状态底纹在深色里饱和度要压到极低（见 3.4 的 bg 值），否则一排徽标会像霓虹灯。**实心圆点保留**——在深色里它是状态最强的识别信号。

### 4.5 引用角标与证据锚点

- 角标：`--accent-weak` 底、`--accent` 字、`--accent-border` 描边。
- 悬浮态：底色转 `--accent`、文字转 `--on-accent`。
- 证据锚点：实心点用 `--accent`；弱证据用 `--warning` 空心环。**空心环的描边宽度从 1.5px 提到 2px**，深色下细线会被吃掉。

### 4.6 引用高亮

用 `--highlight`（`#3A2F1C`）而不是浅色那种明黄。浅黄在暗背景上会形成一块「发光区」，非常刺眼。深色高亮是「微微发暖的暗块」，靠左侧 2px `--accent` 竖条指明位置。

### 4.7 冲突横幅与 diff

| 元素 | 深色做法 |
| --- | --- |
| 冲突横幅 | `--state-danger-bg` 底 + `--state-danger-border` 1px + 左侧 3px `--danger` |
| diff 新增 | `--state-success-bg` + 左侧 3px `--success` |
| diff 删除 | `--state-danger-bg` + 左侧 3px `--danger` + 文字 60% 透明度加删除线 |
| diff 修改 | `--state-warn-bg` + 左侧 3px `--warning` |

**深色下 diff 必须加重左侧竖条。** 纯底色的色差在暗背景上不明显，竖条是最可靠的变更信号。

### 4.8 代码块与滚动条

- 代码块：`--surface-sunken` 底，`--text-primary` 字，四周 1px `--line`。语法高亮只用三色（关键字 `--accent`、字符串 `--success`、注释 `--text-muted`），与浅色一致。
- 滚动条：轨道透明，滑块 `--line` / hover `--line-control`。**不使用系统默认的亮色滚动条**，深色页面里会有一条白杠。

### 4.9 选择与焦点

- 文本选中：`--accent-weak` 底 + `--text-primary` 字。
- 焦点环：2px `--accent` + 2px 偏移。深色下不使用 `outline-style: auto`，各浏览器默认样式在深色里颜色不可控。

## 5. 页面级差异

### 5.1 总览

指标卡底色用 `--surface-canvas`，hover 转 `--surface-sunken`。**不要用发光边框表达 hover**——那是「AI 感」的视觉，与产品气质冲突。未开放的三张卡数字用 `--text-disabled`，不加底色。

### 5.2 知识库

表头 `--surface-sunken`，行 hover `--surface-sunken`，行分隔 `--line-subtle`。导入抽屉 `--surface-raised`，与背后的遮罩形成明确层次。

### 5.3 文档详情

正文 `--surface-canvas`；吸顶条 `--docbar-bg` + 底部 1px `--line`。**深色下背景模糊效果要减弱**，否则移动端滚动时会出现拖影。

右栏 `--surface-app`，比正文更暗，形成「工作区 vs 阅读区」的区分。

### 5.4 问答

用户气泡 `--surface-sunken`，助手回答无底色。证据面板 `--surface-canvas` + 左侧 `--line`。

流式光标用 `--accent` 的实心竖条，不用闪烁方块——闪烁在深色下格外刺眼。

### 5.5 设置

表单卡片 `--surface-canvas`，危险区仅描边 `--state-danger-border`。

### 5.6 Wiki

- 页面树选中项：`--accent-weak` 底 + 左侧 3px `--accent`。
- 状态徽章六态沿用 4.4 的低饱和底纹。
- 反链区用 `--line` 上边框，不加背景。
- 审核队列的选中项：`--surface-sunken` 底 + 左侧 3px `--accent`。

## 6. 媒体内容：深色主题最容易翻车的地方

### 6.1 图片

白底截图在深色页面上会像一块灯箱。但直接反色会毁掉设计稿与图表。

处理方案：**默认给媒体容器加 15% 的暗化遮罩，可在设置中关闭。**

```css
[data-theme="dark"] .media img { filter: brightness(.85); }
[data-theme="dark"].media-dim-off .media img { filter: none; }
```

同时给图片容器加 1px `--line` 边框，让白图有明确边界，而不是和页面融成一片。

### 6.2 PDF

**默认不反色。** pdf.js 的「夜间模式」用 `invert(1) hue-rotate(180deg)`，会把图表颜色、品牌配色、高亮标注全部破坏，对技术材料是负价值。

提供两个选项：

| 模式 | 做法 | 适用 |
| --- | --- | --- |
| 原样（默认） | 白纸照常显示，容器加 1px 边框与轻微外阴影 | 需要的准确性高于舒适度 |
| 夜间阅读 | `filter: invert(.92) hue-rotate(180deg)`，并允许一键切回 | 纯文字的睡前阅读 |

**切换按钮必须常驻在 PDF 工具栏**，不能让用户去设置里找——他会在读一份 PDF 的中途需要切换。

### 6.3 图表

V1 没有图表。V1.5 之后若引入，规则先定好：背景透明，网格线 `--line-subtle`，主色只用 `--accent` 与三个语义色，**不使用彩虹配色**。

## 7. 主题切换：深色特有的四个问题

**问题一：首屏闪白。** 深色用户打开页面时闪一下白，比浅色用户闪黑严重得多。必须在 `<head>` 内联脚本里写 `data-theme`，且 `<body>` 的背景色由 CSS 变量在首帧就生效，不能依赖 JS 加载。

**问题二：打印。** 打印必须强制浅色。深色主题打印出来是一整页黑，既费墨又不可读。规则：`@media print` 下强制 `data-theme="light"` 的变量集。

**问题三：系统主题变化。** 用户选择「跟随系统」时，系统在日落切换主题，页面应实时响应，但**正在播放的音频、正在进行的流式生成不受影响**。

**问题四：截图与导出。** 导出 Markdown / PDF 时使用浅色渲染，不继承用户的深色偏好。否则导出的文档在别人那里打开是黑底。

## 8. 验收

- TD-1：所有正文组合 ≥ 4.5:1，大字与控件边界 ≥ 3:1。
- TD-2：相邻表面层级可辨——相邻两级表面的相对亮度差不低于 1.15 倍。
- TD-3：全站无 `#000000` 与 `#FFFFFF` 作为大面积背景或正文色。
- TD-4：去掉颜色后，状态、diff、冲突仍可由文字、图标或左侧竖条区分。
- TD-5：白底图片不刺眼，且「降低图片亮度」开关生效。
- TD-6：PDF 默认原样显示，夜间模式可一键切回。
- TD-7：首屏无闪白（录屏逐帧检查）。
- TD-8：打印与导出强制浅色。
- TD-9：五页 + Wiki 两态在 390 / 768 / 1024 / 1440 下无横向滚动。
- TD-10：切换主题后，滚动位置、打开的抽屉、音频播放状态不变。

## 9. 风险

| 编号 | 风险 | 说明 | 应对 |
| --- | --- | --- | --- |
| TD-R1 | 低价屏幕的色带 | 深色渐变与低饱和底纹在 6bit 面板上会出现色带 | 状态底纹用纯色不用渐变；必要时加极轻的噪点 |
| TD-R2 | 长时间阅读反而更累 | 深底亮字在明亮环境下对比过强 | 只提供深色，不强制；默认跟随系统而不是默认深色 |
| TD-R3 | 媒体内容破坏整体观感 | 白图、白 PDF 反复打断沉浸 | 6.1 / 6.2 的遮罩与边框是必做项，不是可选美化 |
| TD-R4 | 与浅色主题的维护漂移 | 两套令牌各自演进，出现同一组件两种观感 | 以语义契约为唯一真源，组件禁止写死色值；改一处必须同时改两套 |
