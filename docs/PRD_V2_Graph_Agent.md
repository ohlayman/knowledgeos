## 0. 为什么把这两件事放在同一版

它们看起来无关：一个是知识结构，一个是执行框架。但放在一起有两个具体理由。

**理由一：Agent 的工具集里有一半依赖图谱。** `get_related_knowledge` 这类工具没有图谱就是一个空壳。先做 Agent 再补图谱，等于让 Agent 在 V2 的前半程只能做 V1 的事，白占一版。

**理由二：两者的共同瓶颈是「可解释」。** 图谱要能说清「这两个概念为什么相关」，Agent 要能说清「它为什么这么做」。这两件事用的是同一套能力：把中间过程记录下来并呈现给用户。分开做会各写一套，合起来做只需要一套。

**但交付上必须解耦。** 图谱可以先于 Agent 独立上线并验收；Agent 依赖图谱，不反向依赖。若工期紧张，先交付图谱、Agent 延后，不算版本未完成。

## 1. 版本目标与边界

### 1.1 目标

让系统能回答两类 V1 答不了的问题：

**结构性问题**——「Qdrant 和 BM25 是什么关系」「从 RAG 到 GraphRAG 中间经过哪些概念」。这类问题靠检索片段拼不出来，需要路径。

**执行性问题**——「用我的知识库帮我对比这两个方案，并给出依据」。这类需求不是一次问答，而是多步：检索 A、检索 B、取关系、比较、组织回答。

### 1.2 必须交付

| 能力 | 说明 |
| --- | --- |
| 图谱构建 | 从 V1.5 抽取结果入图，实体归一、关系去噪 |
| 多跳检索 | 1–3 跳路径查询，路径可解释 |
| 图谱可视化 | **3D 为主视图**（可切 2D / 列表）；聚焦两跳、按需展开、节点规模控制、轨道相机与搜索定位 |
| 图谱与问答融合 | 图谱路径作为第三路检索，结果仍回到块 |
| Agent Studio | 配置、工具白名单、执行、预算 |
| 执行记录 | 完整可回放，含每步工具调用 |
| 工具权限 | 只读 + 提案，**没有写入工具** |

### 1.3 明确不做

不做图数据库迁移（PostgreSQL 关系表足够）；不做多 Agent 协作；不做可视化工作流编排；不做 Agent 评测集；不做 Agent 之间的消息传递。

**不做全库图谱渲染。** 节点上万时全量渲染既慢又无意义——用户看的是局部关系，不是星图。

**V2.1 额外不做：** VR/AR、3D 场景导出、自动层级脑图（主题→分支→叶子）、自动布局编辑、多人协同浏览。3D 视图是关系网络的空间化，不是脑图。

### 1.4 前置条件

V1.5 的 AC-V15-1、AC-V15-9（段落有证据锚点）、AC-V15-2（冲突可标记）必须通过。没有来源的实体进图，图谱会变成幻觉的可视化。

## 2. 增量数据模型

### 2.1 Entity（完善 V1.5 的定义）

| 字段 | 要求 |
| --- | --- |
| `canonicalName` | 规范名，唯一索引（按类型 + 规范名） |
| `type` | Concept / Technology / Project / Agent / Protocol，五类，不可增 |
| `aliases` | 别名数组，人工维护 |
| `mentionCount` | 被提及次数（派生） |
| `sourceChunkIds` | 来源块集合，**不得为空** |
| `confidence` | 0–1，由来源数量与抽取置信度合成 |
| `status` | `active` / `merged` / `archived` |

**合并的语义：** 实体合并后，旧实体置 `merged` 并指向新实体，**不物理删除**。历史关系仍指向旧 ID，查询时解析到新 ID。这样合并可逆，误合并可以拆开。

### 2.2 Relation

| 字段 | 要求 |
| --- | --- |
| `fromEntityId` / `toEntityId` | 两端实体 |
| `type` | 九种之一：RELATED_TO / DEPENDS_ON / USES / IMPLEMENTS / REFERENCES / PART_OF / COMPETES_WITH / EXTENDS / CONFLICTS_WITH |
| `direction` | 有向 / 无向。**只有 RELATED_TO 允许无向**（它本身对称），其余八种必须有向 |
| `evidenceChunkIds` | 至少一个 |
| `confidence` | 0–1 |
| `origin` | `extracted` / `human` / `conflict` |

**约束：** 同一对实体同一类型只能有一条有效关系；重复抽取时合并证据，不新增行。

### 2.3 EntityMention

记录「某个实体在某个块的哪个位置出现」，用于可视化时高亮原文。字段：实体、块、起止偏移。

**为什么要单独建表。** 没有它，点击图谱节点只能跳到文档，不能高亮到具体那句；而高亮恰恰是「这条关系有据可查」的证明。

### 2.4 Agent 相关

| 实体 | 关键字段 |
| --- | --- |
| `Agent` | 名称、描述、systemPrompt、模型、温度、工具白名单、步数上限、预算、状态 |
| `AgentVersion` | 每次修改配置生成新版本，执行记录引用版本 ID |
| `AgentRun` | Agent 版本、触发方式、输入、状态、总步数、总耗时、总 token、终止原因 |
| `RunStep` | 序号、类型（思考/工具调用/输出）、模型输出摘要、耗时 |
| `ToolCall` | 步序号、工具名、参数（脱敏后）、返回摘要、状态、耗时、错误码 |

**约束：** `AgentRun` 必须记录 `agentVersionId`。否则改了提示词之后，旧记录无法复现，回放功能就是假的。

## 3. 图谱构建

### 3.1 数据来源

只用 V1.5 已抽取的实体、关系、事实。**V2 不重新调用模型做抽取**，避免同一份材料被抽两遍、两套结果打架。

### 3.2 入图门槛

一条关系要进图，必须同时满足：

其一，两端实体都是 `active`，且各自至少有一个来源块。

其二，关系至少有一个来源块，且该块存在。

其三，关系类型在九种枚举内。

其四，置信度不低于阈值（默认 0.6，可调）。

**不满足的进「待定关系」区，不进图。** 用户可以手动确认，确认后 `origin=human`。

### 3.3 实体归一

**规则一：别名精确匹配。** 规范化后命中别名表即合并。

**规则二：同类型 + 高相似度 → 生成合并建议，不自动执行。** 与 V1.5 的归属判定一致：合并是不可逆的认知损失，宁可多一个节点。

**规则三：合并需人工确认，且可撤销。** 撤销依赖 2.1 的 `merged` 状态，不删数据。

### 3.4 关系去噪

抽取出的关系里，噪声主要来自两类：一是共现误判（两个词在同一段出现就判为 RELATED_TO），二是类型误判（把 USES 判成 DEPENDS_ON）。

处理：

- **共现不构成关系。** 只有模型明确给出关系类型且有证据句支持时才入图。
- **RELATED_TO 是最弱的关系**，只能由人工或两次以上独立抽取产生，单次抽取的 RELATED_TO 进入待定区。
- **CONFLICTS_WITH 只能由 V1.5 的冲突检测产生**，不允许模型自由生成。

### 3.5 规模与性能

V2 的设计规模是 **5 万实体、20 万关系以内**，PostgreSQL 关系表 + 邻接查询足够。超过这个量级再评估图数据库，**不要提前迁移**。

## 4. 多跳检索

### 4.1 什么时候走图

**触发条件（全部满足）：**

其一，问题中识别出两个以上实体；

其二，这两个实体在图谱中距离 ≤ 3 跳；

其三，问题类型属于「关系型/对比型」，而不是「事实型」。

**不满足就不走图。** 这是本版最重要的一条克制：如果每个问题都跑一次图查询，延迟增加、噪声上升，而大多数问题并不需要路径。

### 4.2 路径评分

一条路径的得分由三部分相乘：

**关系置信度乘积** × **来源质量均值** × **跳数惩罚**。

**跳数惩罚不是线性的。** 两跳的路径不一定比三跳好——一条两跳但关系都是 RELATED_TO 的路径，不如一条三跳但关系明确（USES → DEPENDS_ON → IMPLEMENTS）的路径。因此惩罚只作用于「弱关系类型」，不对跳数本身重罚。

### 4.3 结果必须回到块

图谱查询返回的是**路径 + 每条边的证据块**，不是「答案」。这些块再进入 V1 的证据装配流程，与向量、关键词两路结果一起做 RRF 融合。

**图谱不能直接生成回答。** 路径只是关系假设，必须有原文支撑；否则就是在用结构化的方式编造。

### 4.4 可解释性

每条路径要能回答三个问题：

- 经过了哪些节点、哪些关系？
- 每条关系来自哪一段原文？
- 为什么这条路径比另一条更可信（得分构成）？

界面上呈现为一条可点击的链：`Qdrant —USES→ 稀疏向量 —PART_OF→ 混合检索`，每段可展开看来源。

## 5. 图谱可视化（V2.1：3D 为主）

### 5.1 视图形态与切换

**桌面端（≥1024px）默认 3D。** 打开 `/graph` 即进入 3D 视图；工具条提供「3D / 平面 / 列表」三态切换，选择写入 `localStorage`，下次打开沿用。

**2D 与列表不是废弃路径。** 768–1023px 默认 2D；≤767px 默认列表；WebGL 不可用或上下文丢失时自动回落到 2D，并给出提示。列表视图继续承担移动端与屏幕阅读器的可用性。

**3D 使用路由级懒加载。** 首次进入图谱页才加载 Three.js 与图组件；其他页面不得因此增加首屏体积。

### 5.2 3D 交互模型

**相机。** 左键拖拽旋转、滚轮缩放、右键或双指平移；提供「重置视图」回到默认机位。相机操作不得触发节点选中。

**点击节点。** 选中节点、打开详情抽屉、展开一跳邻居；已展开的节点不重复请求。点击空白处取消选中，但不清空已加载的视图。

**悬停节点。** 高亮该节点与直接邻居，边显示关系类型；移出后恢复。

**搜索定位。** 输入实体名后选中目标并让相机飞到该节点；不清空已有视图，不重置相机以外的状态。

**双击。** 双击节点聚焦并展开；双击空白重置视图。

**节点拖拽。** 默认关闭，开启后只固定被拖拽节点的位置，不持续加热整张图。

**统一动作。** 3D、2D、列表共用同一份节点/边状态、同一个详情抽屉与同一个展开接口；切换视图不重新请求已加载的数据。

### 5.3 视觉编码

节点用**几何体**区分类型（球体 / 立方体 / 四面体 / 八面体 / 棱柱），不用五种高饱和颜色；选中使用强调色，冲突使用危险色。

标签使用 SpriteText / CSS2D：≤150 节点全部显示；151–400 仅显示选中、邻居与 hover；>400 走聚合。

边用线型区分：事实关系实线、待定关系低对比细线（3D 引擎不支持虚线，虚线保留在 2D）、冲突关系红色加粗；箭头表示方向，hover 显示关系类型。

**禁止：** 发光节点、Bloom 后处理、渐变连线、粒子流、持续力导向抖动。背景保持近纸色；允许叠加 24px 点阵作为空间参照。

### 5.4 规模与性能

| 当前节点数 | 3D 行为 |
| --- | --- |
| ≤ 150 | 正常渲染，显示节点标签 |
| 151–400 | 隐藏次要标签，仅选中/邻居/hover 显示 |
| > 400 | 提示「当前视图过大，已聚合」，按类型聚合成簇，点击簇再展开 |

3D 视图硬上限：**500 节点 / 2000 条边**，超出先聚合再渲染。布局使用 `warmupTicks=40`、`cooldownTicks=120`，`onEngineStop` 后冻结渲染循环；展开或搜索时只做一次短重排，不做持续抖动。

首帧目标 ≤2s（本机、入口 20 节点）；400 节点目标 ≥30fps。首帧 >4s 或连续 5s 低于 20fps 时，提示「3D 可能较慢」并提供一键切到 2D；不强制自动切换。

### 5.5 降级与无障碍

**WebGL 不可用或上下文丢失** → 1s 内切到 2D，并提示「当前设备不支持 3D，已切换到平面视图」。

**屏幕阅读器与键盘** → 提供一个视觉隐藏但可聚焦的节点列表，节点按钮与画布共享「选中 / 展开 / 搜索定位」动作；`Tab` 进入列表，`Enter` 展开，`Esc` 关闭抽屉。

**移动端** → 默认列表；只有宽度 ≥1024 且 WebGL 可用时才允许切到 3D。

## 6. Agent Studio

### 6.1 Agent 的定义边界

Agent 与「带提示词的问答」的区别有四点，缺一就不是 Agent：**有工具**、**多步**、**可失败恢复**、**可回放**。

如果一个需求只是「换一套提示词回答」，它应该留在 AI Research，不需要新建 Agent。

### 6.2 配置项

| 项 | 约束 |
| --- | --- |
| 名称、描述 | 必填 |
| System Prompt | 必填，有版本 |
| 模型与温度 | 从已配置的模型中选择 |
| 工具白名单 | 默认只开只读检索类 |
| 步数上限 | 默认 8，上限 12 |
| 预算 | 单次执行的 token 上限与工具调用次数上限 |
| 是否允许提案工具 | 默认关闭 |

### 6.3 工具清单

| 工具 | 类型 | 说明 |
| --- | --- | --- |
| `search_knowledge` | 只读 | 混合检索 |
| `get_chunk` | 只读 | 取块全文 |
| `read_wiki_page` | 只读 | 读已发布 Wiki 页面 |
| `get_related_knowledge` | 只读 | 图谱邻域 |
| `summarize_document` | 只读 | 单文档摘要 |
| `propose_wiki_update` | 提案 | 只产提案，不落库，默认关闭 |

**没有写入类工具。** 这不是「默认关闭」，是根本不存在——一旦存在，任何提示注入都可能造成不可逆的知识污染。

### 6.4 执行约束

**步数上限。** 达到上限即终止，并在记录中写明「因步数上限终止」，不允许静默截断。

**预算。** 单次执行的 token 与工具调用次数双重上限，任一触顶即终止。

**工具参数校验。** 每个工具的参数在服务端用 Schema 校验；校验失败返回结构化错误给模型，让它自行修正，而不是抛异常终止。

**失败恢复。** 单个工具失败不终止执行，模型可以换路径；连续三次同类失败则终止并说明。

### 6.5 执行记录

一次执行要能完整回放：输入、每一步的模型输出摘要、每次工具调用的参数与返回摘要、耗时、终止原因。

**参数要脱敏。** 涉及密钥、文件路径的字段在记录中替换为占位符，只保留结构。

**记录不可编辑。** 用户可以删除整条记录，但不能修改其中的步骤——否则「可回放」就没有意义。

### 6.6 成本

Agent 是产品里最贵的功能。要求：

- 执行前显示预估成本区间（基于历史同类执行的中位数）。
- 单日 Agent 总 token 预算可配置，超限后暂停新执行并提示。
- 执行记录中记录实际消耗，供复盘。

## 7. 权限与安全

### 7.1 工具权限

白名单在**服务端**强制执行。模型说「我要调用 X」不算授权，服务端按白名单过滤后才执行。

V2 是单用户，但权限模型按 V3 的令牌作用域预留：工具调用时可携带访问范围，超范围的文档不返回。

### 7.2 提示注入

知识库内容一律视为**数据**，不进入系统提示词区。文档里出现「忽略之前的指令」不改变 Agent 行为。

**V2 必须有测试用例：** 在导入的文档中植入注入文本，验证 Agent 不执行未授权工具、不越权读取。

### 7.3 图谱的隐私边界

图谱会把分散在多个文档里的实体关系集中呈现，**这本身是一种信息聚合**。若未来引入多用户或共享，图谱会成为越权泄露的通道。V2 单用户不受影响，但接口层必须支持按文档范围过滤。

## 8. 页面信息架构增量

```text
/graph                 图谱浏览
/graph?focus=<id>      聚焦某节点
/agents                Agent 列表
/agents/:id            配置与最近执行
/agents/:id/runs       执行记录列表
/agents/runs/:runId    单次执行详情（回放）
```

问答页的证据面板新增一个「关系路径」Tab，当本次检索走过图谱时出现；没走则不显示，**不显示为空 Tab**。

## 9. 接口增量

| 资源 | 能力 | 关键约束 |
| --- | --- | --- |
| 实体 | 列表、详情、邻域查询 | 邻域必须带跳数参数，默认 1，上限 3 |
| 关系 | 列表、详情、待定关系确认 | 确认后 `origin=human` |
| 合并 | 建议列表、执行合并、撤销 | 撤销依赖 `merged` 状态，不删数据 |
| 路径 | 两点之间路径查询 | 返回路径与每条边的证据块 |
| Agent | 增删改查、发布版本 | 修改配置生成新版本 |
| 执行 | 触发、查询、取消、删除记录 | 触发需预算校验 |
| 工具 | 列表（含可用性） | 返回每个工具的参数 Schema |

**路径查询必须返回证据块 ID**，否则前端无法做「这条关系有据可查」。

---

## 10. 非功能要求

| 项 | 要求 |
| --- | --- |
| 图谱邻域查询 | P95 ≤ 200ms（两跳、节点 ≤ 500） |
| 路径查询 | P95 ≤ 400ms（3 跳以内） |
| 画布渲染 | 400 节点 ≥ 30fps，超过则聚合 |
| 3D 首帧 | 本机 ≤ 2s（入口 20 节点） |
| 3D 布局冻结 | 120 tick 内停止；冻结后无持续动画 |
| 3D 懒加载体积 | ≤ 450KB gzip，且只进入图谱页时加载 |
| 3D 降级 | WebGL 不可用 / 上下文丢失 ≤ 1s 切到 2D |
| Agent 首步响应 | P95 ≤ 3s |
| Agent 单次执行 | 上限 120s，超时终止并记录 |
| 并发 | 同时最多 2 个 Agent 执行 |
| 存储 | 5 万实体 / 20 万关系以内不引入图数据库 |

## 11. 验收

- AC-V2-1：给定两个有路径的实体，路径查询返回 ≤3 跳的结果，每条边都有可解析的证据块。
- AC-V2-2：点击图谱节点展开一跳，已展开的邻居不重复加载；节点数超过 400 时自动聚合。
- AC-V2-3：问一个关系型问题，证据面板出现「关系路径」Tab；问一个事实型问题，该 Tab 不出现。
- AC-V2-4：构造一条 RELATED_TO 的弱关系，它不进入图谱主视图，只出现在待定区。
- AC-V2-5：合并两个实体后，历史关系仍可查询，撤销合并后恢复原状。
- AC-V2-6：Agent 执行达到步数上限时终止，记录中写明原因，不产生第 13 步。
- AC-V2-7：工具参数非法的场景下，模型收到结构化错误并尝试修正，执行不崩溃。
- AC-V2-8：在文档中植入提示注入文本，Agent 不调用未授权工具。
- AC-V2-9：执行记录可完整回放，参数已脱敏，步骤不可编辑。
- AC-V2-10：单日 Agent 预算耗尽后，新的执行被拒绝并给出明确提示。
- AC-V2-11：图谱节点点击可跳转到对应块并高亮该实体在原文中的位置。
- AC-V2-12：删除一条执行记录后，其余记录与成本统计仍正确。

### V2.1 3D 图谱验收

- AC-V2.1-1：桌面端打开 `/graph` 默认显示 3D；可切换「3D / 平面 / 列表」，刷新后保持上次选择。
- AC-V2.1-2：左键拖拽旋转、滚轮缩放、右键/双指平移可用；「重置视图」回到默认机位。

- AC-V2.1-4：搜索实体后相机飞到目标并高亮，已有视图不清空。
- AC-V2.1-5：悬停节点高亮直接邻居，边显示关系类型；移出后恢复。
- AC-V2.1-6：节点几何体可区分类型，冲突边为红色加粗；无发光、无粒子流、无持续抖动。

- AC-V2.1-9：视觉隐藏的节点列表可用键盘操作，按钮与画布共享展开/选中动作。
- AC-V2.1-10：3D 依赖只在进入图谱页时加载，其他路由不增加 Three.js 体积；首帧与帧率达标，低于阈值时出现「切到平面视图」提示。

## 12. 风险

| 编号 | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| V2-R1 | 图谱噪声高，用户不再相信 | 关系页沦为摆设 | 入图门槛严格；待定区隔离；RELATED_TO 需双重确认 |
| V2-R2 | 多跳检索拖慢问答 | 首 token 延迟上升 | 只在关系型问题触发；图谱路径作为第三路并行，不阻塞主路 |
| V2-R3 | Agent 成本失控 | 单次执行烧掉大量 token | 预算双上限、执行前预估、单日总额度 |
| V2-R4 | 画布性能崩坏 | 页面卡死 | 400 节点聚合、默认两跳、不做全库渲染 |
| V2-R5 | 提示注入导致越权 | 数据泄露或误改 | 服务端白名单 + 内容视为数据 + 专项测试 |
| V2-R6 | 图谱与 Wiki 的实体不一致 | 同一概念两套名字 | 统一使用 V1.5 的实体表，不另建 |
| V2-R7 | 3D 可读性差，节点互相遮挡 | 用户退回列表，3D 成为摆设 | 限制标签数量、近纸色平面材质、选中/邻居优先；保留 2D |
| V2-R8 | Three.js 体积拖慢图谱页 | 首次打开明显变慢 | 路由懒加载；≤450KB gzip；骨架屏 |
| V2-R9 | WebGL 在部分设备不可用 | 页面空白 | 启动探测 + 上下文丢失监听 + 1s 内切 2D |
| V2-R10 | 3D 破坏「安静纸感」 | 与整体设计语言冲突 | 禁发光/渐变/粒子；布局冻结；只保留选中与冲突两种强调色 |
